# Loop Engineering — pcr-tool

対象: 上流由来のPCR Toolリポジトリ（既存開発ブランチを保護）。
正本候補: README.md、CHANGELOG.md、DATATABLE.md、既存のビルド/CI設定

## 1サイクルの実行
1. 現状: AGENTS.md/README/Issue/未コミット変更/失敗記録を確認。
2. 選定: READYがなくても実在する未完了を切り出し、独立した安全な最小タスクを1件選ぶ（候補: 既存issue・再現可能な差分からfork固有の最小修正1件。なければNO_TASK）。根拠がなければNO_TASK。
3. 仮説: 再現条件・修正範囲・合格条件を定義。
4. 実装: 許可済みのワークツリー内のみ最小変更。
5. 検証: 既存のGradle/ビルドタスクを実際のリポジトリから確認した場合のみ実行。テスト不能をPASSとしない。
6. 評価: PASS/BLOCKED_INPUT/BLOCKED_ENV/TEST_INFRA_ERROR/TASK_FAILを実測で分類。
7. 引継ぎ: 変更ファイル、検証ログ、未確認条件、次タスク1件を記録。

## 安全と実行条件
上流のブランチ、権利情報、release資産の自動変更・配布・大量マージは禁止。。同一失敗への無根拠再試行禁止。ブロックしても別の独立案件に進む。停止指示を維持し、結果不明の副作用は照合。ループ処理を無限に継続するのではなくOSスケジューラーが次回を起動する。監視だけでは開発成果でない。

報告: task_id｜仮説｜変更ファイル｜検証と結果｜分類｜ブロッカー｜次のタスク。
